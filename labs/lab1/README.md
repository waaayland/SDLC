# Лабораторная работа №1 — вариант 15

**Дисциплина:** Жизненный цикл разработки программного обеспечения
**Тема:** Интегрированная среда разработки ПО
**Вариант 15:** Разработать генератор паролей.

> Пользователь вводит, сколько символов ему надо в пароле, какие наборы
> символов в пароль включать, сколько паролей надо. На главной форме пусть
> будет кнопка «Ввести данные». По нажатию на нее пусть откроется
> дополнительное окно для ввода указанной информации. Последние введенные
> данные нужно запоминать в главной форме и восстанавливать при повторном
> вводе. После этого на главной форме отобразить результат — упомянутые
> величины. Если введены некорректные данные — показать сообщение об ошибке.
> Добавить каркас MVC **с активной моделью**.

**Язык и среда:** C++17, Qt 6.11.2 (Qt Widgets), MinGW 13.1.0, CMake + Ninja,
Qt Creator.

## ⚠ Настройка Qt Creator: генератор Ninja

Проект лежит в пути с кириллицей (`...\ЖЦРПО\...`). Генератор
**MinGW Makefiles**, который Qt Creator может выбрать по умолчанию,
с такими путями не работает вообще — `mingw32-make` не находит ни
исходники, ни служебные файлы:

```
AutoGen: The info file ".../AutogenInfo.json" is not readable
No rule to make target '.../src/main.cpp'
```

**Один раз настройте комплект на Ninja:**

> Инструменты → Параметры → **Комплекты** → выбрать
> *Desktop Qt 6.11.2 MinGW 64-bit* → поле **«Генератор CMake»** →
> **Изменить…** → Генератор: **Ninja** → OK.
>
> Затем удалить каталог сборки и заново настроить проект
> (Проекты → Настройки сборки → **Настроить заново**).

Если этого не сделать, CMake остановится с подробным сообщением
и подсказкой — загадочных ошибок не будет.

Из командной строки Ninja используется всегда (`build.bat`).

## Замечание: кириллица в пути к проекту

Утилита `moc.exe` из Qt 6 не умеет **создавать** файлы в каталогах,
имена которых содержат кириллицу:

```
moc: Cannot create .../PasswordGenerator_autogen/.../moc_mainwindow.cpp.
Error: No such file or directory
```

Читать исходники из такого пути `moc` умеет — ломается только запись.
Проект лежит по пути `...\ЖЦРПО\...`, поэтому сборка «из коробки»
падала бы у любого, кто откроет её в Qt Creator.

**Это уже обработано в `CMakeLists.txt`:** если каталог сборки оказался
в пути с не-ASCII символами, автогенерируемые файлы (`moc_*`, `ui_*`)
автоматически перенаправляются в `%LOCALAPPDATA%\QtAutogen\<проект>-<хеш>`.
При конфигурировании выводится:

```
-- В пути каталога сборки есть кириллица — moc/uic не смогут туда писать.
-- Автогенерируемые файлы перенаправлены в: C:/Users/.../QtAutogen/PasswordGenerator-2f08baa6
```

Никаких действий не требуется: проект собирается и из кириллического
пути, и из латинского.

Если всё же хочется убрать проблему полностью — включите в Windows
*Параметры → Время и язык → Язык и регион → Административные языковые
параметры → Изменить язык системы → **Бета-версия: использовать Юникод (UTF-8)***
и перезагрузитесь.

## Сборка и запуск

### В Qt Creator (основной способ)

1. **Файл → Открыть файл или проект…** → выбрать `01_LAB/CMakeLists.txt`.
2. Выбрать комплект **Desktop Qt 6.11.2 MinGW 64-bit** → **Настроить проект**.
3. Сборка — `Ctrl+B`, запуск — `Ctrl+R`, отладка — `F5`.

Каталог сборки менять не нужно — кириллица в пути обрабатывается
автоматически (см. раздел выше).

### Из командной строки

Достаточно запустить из проводника или консоли:

```
build.bat
```

Скрипт настраивает `PATH` для Qt/MinGW/CMake/Ninja и собирает проект
в `%USERPROFILE%\QtBuilds\PasswordGenerator`. Запуск — `run.bat`.

Вручную то же самое:

```bash
cmake -S . -B "%USERPROFILE%/QtBuilds/PasswordGenerator" -G Ninja ^
      -DCMAKE_BUILD_TYPE=Release -DCMAKE_PREFIX_PATH="C:/Qt/6.11.2/mingw_64"
cmake --build "%USERPROFILE%/QtBuilds/PasswordGenerator"
```

> При запуске вне Qt Creator в `PATH` должен быть каталог `C:\Qt\6.11.2\mingw_64\bin`
> (там лежат `Qt6Core.dll`, `Qt6Gui.dll`, `Qt6Widgets.dll`) — это делает `run.bat`.
> Для автономного комплекта, который можно перенести на другой компьютер:
> ```bash
> C:/Qt/6.11.2/mingw_64/bin/windeployqt.exe "%USERPROFILE%/QtBuilds/PasswordGenerator/PasswordGenerator.exe"
> ```

## Как работает приложение

1. На главной форме — кнопка **«Ввести данные»**, группа «Последние введённые
   данные» и список «Сгенерированные пароли».
2. По нажатию кнопки открывается **модальное окно ввода**: длина пароля,
   количество паролей и четыре флажка наборов символов (строчные, прописные,
   цифры, специальные).
3. Поля окна заполняются **последними введёнными данными**, которые хранит
   модель, — при повторном вводе ничего не нужно набирать заново.
4. По кнопке **OK** данные уходят контроллеру → модели. Модель проверяет их,
   генерирует пароли и **сама** оповещает главную форму, которая показывает
   параметры и список паролей.
5. При некорректных данных модель оповещает форму об ошибке, и та показывает
   `QMessageBox` с пояснением.

### Алгоритм генерации

`PasswordGenerator::generate()` использует криптографический источник
случайности `QRandomGenerator::system()`. В каждый пароль сначала помещается
по одному символу из **каждого** выбранного набора (чтобы пароль гарантированно
удовлетворял заданным требованиям), остаток добирается из объединённого
алфавита, после чего строка перемешивается алгоритмом Фишера—Йетса.

### Ограничения на ввод

| Параметр | Допустимые значения |
|----------|---------------------|
| Длина пароля | целое число 4…128 |
| Количество паролей | целое число 1…50 |
| Наборы символов | должен быть выбран хотя бы один |
| Дополнительно | длина пароля не меньше числа выбранных наборов |

## MVC с активной моделью

Подробное описание — в [docs/MVC.md](docs/MVC.md). Кратко:

* **Model** (`PasswordModel`) хранит состояние, проверяет данные, генерирует
  пароли и **сам рассылает уведомления** подписанным представлениям через
  интерфейс `IModelObserver` (паттерн Observer). Слой не зависит от Qt Widgets.
* **View** (`MainWindow`, `InputDialog`) реализует `IModelObserver`,
  подписывается на модель и только отображает состояние.
* **Controller** (`PasswordController`) открывает окно ввода и передаёт
  «сырые» данные модели. Экран он **не обновляет** — это и отличает активную
  модель от пассивной.
